# 모임 시작 하루 전 알림 발행 (#78)

## 계약

토픽 `match.starting-soon.v1`, Kafka key는 matchId 문자열이다. payload는 아래 다섯 필드다.

```json
{
  "eventId": "UUID",
  "matchId": 57,
  "title": "주말 풋살",
  "startAt": "2026-11-05T19:00:00+09:00",
  "participantIds": [101, 102, 103]
}
```

startAt은 match_db의 서울 기준 DATETIME을 UTC 오프셋 포함 ISO-8601로 변환한다. 수신자는 이벤트 저장 시점에 확정된 참가자 전원이며 방장을 포함하고 대기열은 제외한다. 회원·시설 API를 다시 호출하지 않는다. 알림 수신·문구·알림함 저장은 notification-service 담당 작업이다.

## 스캔 및 중복 방지

기본 60초마다 확정 참가자가 있는 모임을 최대 100개 조회한다. 수신자가 없는 모임은 조회 한도를 차지하지 않으며, 이후 참가자가 생기면 다시 대상이 된다. 시작 전이고 시작까지 24시간 이내인 RECRUITING·CLOSED 매치를 처리한다. 정확히 24시간 전 한 시각만 비교하지 않으므로 서버 중단으로 놓친 대상도 시작 전에 복구하면 처리된다. 시작까지 24시간 미만인 새 모임도 다음 스캔에서 처리한다. 시작한 모임·취소·완료·진행 상태는 제외한다.

후보 조회 뒤 매치 행 잠금을 얻고 현재 상태·시각을 재검사한 다음 참가자와 Outbox를 한 트랜잭션에서 저장한다. 생성·수정·취소·참가·Saga도 공통 매치 행 잠금을 사용해야 한다. 후보 조회 이후 취소되거나 24시간 밖으로 미뤄진 모임은 저장하지 않는다.

eventId는 `match.starting-soon.v1:<matchId>`에서 생성한 고정 UUID다. 행 잠금, Outbox event_id 기본키, 잠금 아래 발행 이력 조회로 반복·다중 서버·재시작에도 모임당 한 건을 유지한다. 전송 실패 시 기존 relay가 동일 eventId·payload로 재시도하고 ACK 후 published_at을 기록한다.

모임당 한 번 정책이므로 이미 이벤트를 저장한 모임은 시작 시각이 바뀌어도 재발행하지 않는다. 이벤트 저장 이후 변경된 시각·참가자 목록으로 기존 payload를 수정하지 않는다. 저장 이후 취소된 모임의 미전송 이벤트를 철회하는 기능은 포함하지 않으며, 후속 취소 이벤트와 구분한다.

발행 완료 Outbox 행도 발행 이력으로 보존해야 한다. 현재 relay는 행을 삭제하지 않는다. Outbox 청소 정책을 추가하려면 모임당 발행 이력을 별도 영구 저장하거나 기존 발행 키를 보존해야 한다.

## 설정

- MATCH_STARTING_SOON_ENABLED: 기본 true. false면 스케줄러만 중지한다. 기존 Outbox 전송은 별도 match.outbox.enabled 설정을 따른다.
- MATCH_STARTING_SOON_DELAY_MS: 기본 60000.
- MATCH_STARTING_SOON_INITIAL_DELAY_MS: 기본 60000.

스키마·권한·다른 서비스·CRUD Draft #77은 변경하지 않는다. 테스트 기본 설정은 스케줄러를 비활성화하고 테스트에서 명시적으로 스캔해 시각을 고정한다.

## 검증

StartingSoonTest에서 24시간 경계·미만 즉시 대상·시작 후 제외, 취소·진행·완료 제외, 정확한 payload·방장 포함·대기 제외, 반복·재시작·일정 변경·동시 20회 실행 중복 방지, 후보 조회 이후 상태 재검사, 저장 실패 롤백·재시도, 개별 실패 후 다음 모임 처리, Kafka 실패 후 동일 이벤트 재시도를 검증한다.

2026-11-01 매칭 테스트 총 114건 중 102건 성공·조건부 12건 제외·실패 0건이며 bootJar도 성공했다. 공식 R8 MariaDB·DML 앱 계정·validate의 실제 매칭 컨테이너와 Kafka에서도 7항목을 통과했다. Kafka 중단 중 미발행 Outbox 유지, 복구 후 같은 eventId·payload 전달 및 matchId key, 취소·24시간 밖 대상 제외, 실제 컨테이너 재시작 후 한 건 유지를 확인했다. 데이터는 전용 DB의 SQL fixture를 사용했으며 회원·시설·Gateway·알림 수신부는 실행하지 않았다.
